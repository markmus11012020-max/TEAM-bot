# Team Bot — память команды в Telegram

Бот для рабочего чата: слушает переписку, складывает её в векторную память
(Pinecone + Haystack) и умеет отвечать на вопросы по истории, а по команде
`/stop` собирает итоги обсуждения — решения, задачи, споры и собственное
мнение ассистента.

## Что умеет

- **Индексирует все сообщения группы** — текст, подписи к медиа, опросы,
  геолокации и контакты. Для каждого сохраняются автор, username, дата/время,
  ссылка на сообщение, ветка (topic) и цитата ответа.
- **`/start` … `/stop`** — запись обсуждения. `/stop` отправляет стенограмму
  в LLM и присылает структурированные итоги:
  краткое резюме, ключевые пункты, споры с позициями сторон и рекомендацией,
  принятые решения (обоснование, ответственный, срок), задачи, открытые
  вопросы, риски и мнение ассистента.
- **Ответы по упоминанию** — `@бот вопрос` или ответ на сообщение бота.
  Бот ищет по истории чата (RAG) и цитирует, кто что сказал и когда.
- **`/ask вопрос`** — то же самое без упоминания.
- **`/status`** — сколько сообщений в памяти, что в очереди, идёт ли запись.
- **`/help`** — подсказка по командам.

## Как это устроено

```
Telegram update
   │
   ▼
bot/handlers.py ──► SQLite (messages, sessions, summaries)
   │                       │
   │                       ▼
   │              bot/indexer.py (фоновый поток)
   │                       │
   │                       ▼
   │        Haystack: OpenAIDocumentEmbedder → PineconeDocumentStore
   │
   ├── вопрос ──► OpenAITextEmbedder → PineconeEmbeddingRetriever
   │              → ChatPromptBuilder → OpenAIChatGenerator → ответ
   │
   └── /stop ──► стенограмма → (при необходимости сжатие по частям)
                  → JSON-схема итогов → Telegram HTML + Pinecone (kind=summary)
```

- Все входящие сообщения сначала пишутся в SQLite (это очередь и запасная
  копия), затем батчами индексируются в Pinecone. При сбое батча индексатор
  повторяет сообщения по одному и считает попытки.
- Сессия записи хранится в SQLite. Сообщения, пришедшие во время сессии,
  помечаются её `session_id`; итоги тоже сохраняются в базе.
- Один namespace Pinecone, фильтрация по `chat_id` в metadata. При
  `SEARCH_SCOPE=all` бот ищет по всем чатам, которые видел.

## Быстрый старт

Требуется Python 3.11+ (проверено на 3.12).

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
# заполните TELEGRAM_BOT_TOKEN, OPENAI_API_KEY, PINECONE_API_KEY
python -m scripts.smoke_test --all
python bot.py
```

`smoke_test` проверяет версии пакетов, конфигурацию, доступ к LLM,
эмбеддингам и Pinecone. Без флагов он только смотрит окружение.

### Обязательно для групп: privacy mode

По умолчанию Telegram не отдаёт ботам обычные сообщения групп. Включите одно
из двух:

1. `@BotFather` → `/setprivacy` → выберите бота → **Disable**;
2. или сделайте бота **администратором** группы.

После изменения настроек privacy перезапустите бота (или удалите и добавьте
заново), иначе Telegram продолжит присылать только команды и упоминания.

### Pinecone

Нужен аккаунт [Pinecone](https://app.pinecone.io) и API-ключ. Индекс создаётся
автоматически при первом запуске (serverless, `aws/us-east-1` по умолчанию,
метрика cosine, размерность `EMBEDDING_DIMENSIONS`).

Важно: размерность индекса нельзя изменить. Если меняете модель эмбеддингов
на другую размерность — создайте новый индекс и укажите его в
`PINECONE_INDEX`.

## Команды

| Команда | Кто | Что делает |
| --- | --- | --- |
| `/start`, `/listen` | админы (по умолчанию) | начинает запись обсуждения в чате |
| `/stop`, `/finish`, `/stop_listening` | админы | завершает запись и присылает итоги |
| `/status`, `/session` | все | состояние памяти и записи |
| `/ask <вопрос>`, `/q` | все | ответ по истории чата |
| `/help` | все | справка |

`COMMAND_ACCESS=admins` разрешает `/start` и `/stop` только пользователям из
`ADMIN_USER_IDS`. Если список пуст, управление записью отключено (в лог
пишется предупреждение) — заполните `ADMIN_USER_IDS` или поставьте
`COMMAND_ACCESS=everyone`, чтобы разрешить команды всем участникам.

Бот также отвечает, когда его упоминают (`@username`) или отвечают на его
сообщение. Есть антифлуд: не чаще одного ответа на пользователя раз в
`ANSWER_COOLDOWN_SECONDS`, и не отвечает на упоминания старше
`MAX_ANSWER_AGE_SECONDS` (например, накопившиеся за время простоя).

## Настройки

Все параметры читаются из `.env` (см. `.env.example`). Основные:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | — | токен от `@BotFather` |
| `OPENAI_API_KEY` | — | ключ OpenAI-совместимого API (AITUNNEL) |
| `OPENAI_BASE_URL` | `https://api.aitunnel.ru/v1` | base URL для LLM |
| `CHAT_MODEL` | `deepseek-v4.1-flash-1017` | модель генерации |
| `LLM_MAX_TOKENS` | `2000` | лимит ответа |
| `LLM_MAX_TOKENS_PARAM` | `max_tokens` | `max_tokens`, `max_completion_tokens` или `none` |
| `LLM_TEMPERATURE` | пусто | если пусто — параметр не передаётся |
| `STRUCTURED_SUMMARY` | `true` | JSON Schema для итогов + fallback на текст |
| `EMBEDDING_MODEL` | `text-embedding-3-small` | модель эмбеддингов |
| `EMBEDDING_DIMENSIONS` | `1536` | размерность индекса |
| `EMBEDDING_SEND_DIMENSIONS` | `false` | передавать `dimensions` в API эмбеддингов |
| `PINECONE_API_KEY` | — | ключ Pinecone |
| `PINECONE_INDEX` | `team-bot` | имя индекса |
| `PINECONE_NAMESPACE` | `team-chat` | namespace |
| `COMMAND_ACCESS` | `admins` | кто может управлять записью |
| `ADMIN_USER_IDS` | пусто | ID админов через запятую |
| `ALLOWED_CHAT_IDS` | пусто | ограничить бота чатами |
| `SEARCH_SCOPE` | `chat` | `chat` — только текущий чат, `all` — все |
| `RETRIEVAL_TOP_K` | `12` | сколько фрагментов достаёт поиск |
| `RECENT_MESSAGES` | `25` | сколько последних сообщений добавлять к контексту |
| `SESSION_IDLE_TIMEOUT_MINUTES` | `0` | автозакрытие записи при простое (0 — выкл.) |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс в стенограмме и итогах |
| `DB_PATH` | `data/team_bot.sqlite3` | файл SQLite |

Ключи эмбеддингов можно задать отдельно (`EMBEDDING_API_KEY`,
`EMBEDDING_BASE_URL`) — по умолчанию используются ключи LLM.

## Итоги сессии

1. `/stop` закрывает сессию и запускает обработку в отдельном потоке.
2. Стенограмма собирается из SQLite: `[дата время] Автор (@username): текст`,
   рядом — цитата сообщения, на которое ответили.
3. Если стенограмма больше `SUMMARY_CHUNK_CHARS`, она сжимается по частям
   отдельным пайплайном (конспект каждой части), затем итоги строятся по
   конспектам.
4. Модель возвращает JSON по схеме (резюме, тип обсуждения, пункты, споры,
   решения, задачи, вопросы, риски, мнение). Если провайдер не поддерживает
   structured outputs — автоматически используется обычный текстовый ответ.
5. Итоги отправляются в чат красивым HTML (с разбиением на несколько
   сообщений) и сохраняются в SQLite и Pinecone (`kind=summary`), чтобы
   позже попадать в ответы на вопросы.

## Docker

```powershell
copy .env.example .env   # заполнить ключи
docker compose up -d --build
docker compose logs -f
```

База хранится в named volume `team-bot-data`. Если нужен bind mount,
замените volume на `./data:/app/data` и заранее создайте каталог с владельцем
uid 1000 (пользователь `bot` в контейнере).

## Частые проблемы

- **Бот не видит сообщения в группе** — включён privacy mode. См. раздел выше.
- **`409 Conflict` в логах** — запущено два экземпляра бота с одним токеном.
- **`Размерность индекса ... не совпадает`** — индекс создан под другую модель
  эмбеддингов; создайте новый индекс.
- **Итоги не приходят, в логах ошибка API** — проверьте `OPENAI_BASE_URL`,
  `CHAT_MODEL`, лимиты ключа; прогоните `python -m scripts.smoke_test --llm`.
- **Модель не поддерживает JSON Schema** — поставьте `STRUCTURED_SUMMARY=false`
  или смените модель: бот продолжит работать с текстовыми итогами.
- **Смена модели/провайдера** — достаточно поменять `CHAT_MODEL` и
  `OPENAI_BASE_URL`; для эмбеддингов помните про размерность индекса.

## Ограничения

- Бот не расшифровывает голосовые и не распознаёт текст на картинках — такие
  сообщения индексируются как пометка о типе вложения (и подпись, если есть).
- История ограничена тем, что бот видел после добавления в чат.
- Итоги и ответы генерирует LLM: возможны неточности, поэтому в промптах
  запрещено выдумывать факты, а в ответах указываются автор и время реплик.
- Один процесс обслуживает один токен; для нескольких команд используйте
  отдельные экземпляры и разные `PINECONE_INDEX`/namespace.
